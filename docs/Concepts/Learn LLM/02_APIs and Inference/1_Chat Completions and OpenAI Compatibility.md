## The Chat Completions API Standard

The **Chat Completions API** was introduced by OpenAI to standardise interactions with conversational models. Instead of treating text generation as arbitrary string completion, it models communication as an ordered sequence of role-tagged messages: "Given this prior dialogue history, predict what message comes next."

Because of its simplicity and popularity, it has become the *de facto* universal standard for generative AI across the industry.

---

## Role-Based Message Structure

Conversations are represented as a list of message objects, each assigned a specific `role`:

| Role | Purpose | Example / Function |
| :--- | :--- | :--- |
| **`system`** | Sets model behavior, guardrails, tone, output format, or domain constraints. | `"You are an expert tutor explaining algebra in markdown."` |
| **`user`** | Prompts, queries, or replies provided by the human end-user. | `"Explain how to solve (a + b)^2 step-by-step."` |
| **`assistant`** | Previous replies generated by the model, injected to maintain dialogue history. | `"To expand (a + b)^2, we apply the binomial theorem..."` |

## Raw HTTP vs Python SDK

Because the Chat Completions API is simply an HTTP POST endpoint, it can be called using standard web libraries:

### 1. Raw HTTP POST (`requests`)

```python
import os
import requests

api_key = os.getenv("OPENAI_API_KEY")
headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json"
}

payload = {
    "model": "gpt-4o-mini",
    "messages": [
        {"role": "system", "content": "You are a concise engineering assistant."},
        {"role": "user", "content": "Tell me a fun computer science fact."}
    ],
    "temperature": 0.7
}

response = requests.post(
    "https://api.openai.com/v1/chat/completions",
    headers=headers,
    json=payload
)

data = response.json()
print(data["choices"][0]["message"]["content"])
```

### 2. Strongly Typed Client (`openai` SDK)

To eliminate manual JSON serialization, status code parsing, and connection retries, the official Python SDK provides a strongly typed interface:

```python
from openai import OpenAI

client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "You are a concise engineering assistant."},
        {"role": "user", "content": "Tell me a fun computer science fact."}
    ]
)

print(response.choices[0].message.content)
```

## OpenAI-Compatible Endpoints

Most model providers and local inference tools (including Ollama, vLLM, Groq, Together AI, Mistral, and OpenRouter) expose **OpenAI-compatible endpoints**.

By altering only `base_url` and `api_key`, developers can switch between cloud providers and local runtimes without changing any client application logic:

```python
from openai import OpenAI

# Switching seamlessly from OpenAI Cloud to Local Ollama:
local_client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"  # Required by SDK, ignored by local daemon
)

response = local_client.chat.completions.create(
    model="llama3.2",
    messages=[
        {"role": "user", "content": "What is the difference between TCP and UDP?"}
    ]
)

print(response.choices[0].message.content)
```
